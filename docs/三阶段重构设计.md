# 系统设计说明：基于智能手表传感器的进食检测

版本 3.3（2026-09-17）。本文记录当前真实的 event-stack 架构、严格五折证据、发布
契约和后续边界；历史迭代的过程性细节已压缩到根目录 README 的简表与 git 历史。
交付重构（canonical `src/pipeline`、raw Predictor、`dist/inference`/`dist/submission`、
清理台账）见 README 与 `docs/repository_cleanup_audit.md`。

## 1. 任务与评估口径

输入为智能手表 IMU（ACC+GYRO，约 105 Hz，原始 ADC；PPG 有效采样约 2 Hz）。输出为
Episode 起止时间。预测与 GT 的 IoU ≥ 0.25 记为 TP，
`recall=TP/eligible truths`、`PPV=TP/predictions`、`F1=2·recall·PPV/(recall+PPV)`。
当前锁定 eligible 分母为 153 个事件；短餐切片为 `<10 min` 的 39 个事件。

## 2. 当前架构（event-stack）

```
真实时间戳、缺口切段
  ├─ macro：240 s / 15 s 全覆盖，63 维（62 ACC 统计 + time prior）
  └─ micro：15 s / 7.5 s ACC+GYRO，47 维
       → macro ∪ micro 候选
       → 同 sid 稳定 NMS（IoU）
       → subject admission（阈值 + 每 subject cap）
       → 56 维基础事件特征 + Context-v1 60 维 session-local 上下文（116 维）的 LogisticRegression + LightGBM 概率 blend
       → 冻结 event policy（事件阈值、几何和预算）
       → 官方 IoU 评估 / canonical JSON
```

macro 窗模型只在 outer-train 拟合；micro 分支用于补足短餐候选。NMS 的几何作用域是
同一 `sid`，candidate admission 和 event budget 的作用域是稳定的 `subject_id`。
同一 payload 的 `sid` 必须全局唯一，防止会话边界被错误合并。

## 3. 严格 nested 协议

外层每折先锁定 validation subject；在 outer-train 内进行四路 subject-disjoint OOF：
窗模型、micro 模型、Logistic verifier 与 LightGBM verifier 各只给未见过该 subject 的
样本打分。融合权重、NMS IoU、admission threshold/cap、事件阈值和预算只由这些 OOF
结果选择；随后在完整 outer-train 重训，outer validation 只评分一次。outer truths、
labels、slice labels 和外层结果均不得影响选择。重复 outer-CV 是开发证据，不是 untouched
测试集泛化估计。

当前配置固定：`no_tcn=true`、`external_fd_weight_grid=(0.0,)`、macro/micro/verifier
维度为 63/47/116（Context-v1 schema-v2），micro threshold grid 为 0.10/0.20/0.30/0.40/0.50，blend weight
grid 为 0/0.25/0.5/0.75/1，admission IoU/threshold/cap 网格由 run config 固化。

## 5. 模型固化、provenance 与设备契约

模型根为 `models/event_stack/160afaf81debf1ee/`，包含五个 outer-fold evidence、
`deployment/` full-target 模型、`promotion_summary.json` 和
`promotion_attestation.json`。deployment 只拼接经过校验的五个 outer-validation 分区，
不把外层标签用于策略选择；其 manifest 保存输入文件 canonical path、size、mtime_ns、
SHA-256、特征维度和依赖版本。attestation 同时绑定 canonical summary、五折和每个
manifest 的 SHA-256。`dist/event_stack/` 只能由注册打包器从该 deployment 原子生成。

当前后端是 CPU-only：`--device auto` 解析为 CPU，`--device cpu` 强制 CPU，`gpu/cuda`
在 CUDA 不可用或没有显式 CUDA adapter 时必须报错。当前 adapter registry 为空，不能
以 CPU/CUDA 输出一致推断实际使用了 GPU。

原始会话推理已就绪：`src/pipeline/inference` 的 `Predictor` 直接读取 `collect_data*.txt`
（canonical raw 62/47 特征 → 冻结 time-prior 适配 → 模型 → admission → 解码），并由
`dist/inference`（`predict.py`）与 `dist/submission`（`main.py`）提供自包含包；四路
boundary parity（legacy = canonical = dist/inference = dist/submission）为发布门禁。
`dist/submission` 是竞赛最终交付物，额外包含完整模型证据链（deployment + 五折
evidence + attestation）、复现代码（src/scripts/tests）与可视化工作区
（visual/ + schema/examples）；文档随仓库维护、不进入提交包。旧发布包 `dist/event_stack` 保留为 serialized-payload
运行时（预计算 macro 63 / micro 47 / verifier 116 维 JSON + 稳定 `subject_id` 与
全局唯一 `sid`），作为发布证据，新集成一律使用 `dist/inference`。

## 6. 审计结论与决策时间线

1. 时间轴审计修复 `WINDOW_MS=525000` 毫秒/行数混用及行号轴漂移，旧 0.319/0.333
   作废；统一真实包级时间戳与 153-event eligible 分母。
2. 第二轮 peer review 确认 v5.1 跨折 wbag 泄漏，0.617/0.632 作废；确认 LOSO verifier
   曾见留出受试者，严格重训后 LOSO 为 0.416（67/153）。TCN 研究配置干净协议有效，
   但发布路径 no-TCN 保持 CPU 同构。
3. 组内方案的 15s ACC+GYRO、旋转稳健 GYRO 特征和 1Hz 平滑值得迁移；其 0.652/0.499
   因纯负会话缺失、阈值/正类提纯未嵌套等协议风险不能直接横比。
4. 微窗并集改善短餐并达到 F1 0.478632，但 raw union 3,413 超过预注册 612 候选体积门，
   因此只保留为历史证据。candidate-control + stacking 随后在同一 nested 协议下将
   F1 提升到 0.5432098765；随后把 admission 最低召回约束由 0.88 降至 0.80，F1
   提升到 0.5589743590，并把 admission 候选降至 299。

## 7. 后续边界与迁移路线

raw-session 推理与四路 parity 已完成（见 §5）；官方提交 I/O adapter 未注册，提交包
官方模式显式拒绝（不猜格式）。算法侧的下一步是短餐与餐时 hard-negative/候选簇去重。
FD-I/FD-II 迁移必须另立门控实验，优先以同一 15s 表示训练 gesture encoder，并保留
随机初始化与 `external_weight=0` 对照；WIMID/CAD 在许可证确认前不进入训练。
FD-I/FD-II 的 CC BY-NC-ND 4.0 条款、署名和衍生物限制必须随模型发布一起审查。

## 8. 复现

```bash
conda activate bme
# 只验证发布链（registry + attestation + 5+1 bundle + dist 清单，不重训）
python scripts/reproduce_release.py --run-key 160afaf81debf1ee
# 严格 nested 评估（新入口 = crossfit_event_stack 的同参数薄封装）
python scripts/evaluate_event_stack.py --fold all --inner-splits 4 --no-tcn --workers 5 \
  --micro-enabled --candidate-control-enabled --admission-minimum-recall 0.80 \
  --context-features v1 --summary-alias outputs/crossfit/context_v1_summary.json
python scripts/release_event_stack.py --summary outputs/crossfit/context_v1_summary.json
# 重建分发包（生成物，勿手改）
python scripts/build_inference_distribution.py
python scripts/build_submission.py
# 快速推理
python dist/inference/predict.py path/to/collect_data1_2_3.txt --output prediction.json
```

一次性 micro 特征缓存可先运行 `scripts/build_micro_features.py --fold all --split all`；
重复评估会复用内容寻址缓存。详细数据清洗和时间戳规则见 `docs/数据处理说明.md`，
正式审计表见 `docs/组内算法对比与外部数据审计.md`，文献材料见 `ReferenceDocs/`。
